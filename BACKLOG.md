## Ideas (proposed by night job)
- Top-up plan in buyable units: gold in whole 1/10 oz coins at the current coin price, with what is left over re-split between the other assets. Reason: P17's plan can say "gold 417 PLN" while a coin costs several times that, so its gold line cannot be bought as is.
- (S) Kraken balance reconciliation: after each sync, compare the `Balance` endpoint per asset with the positions derived from the stored ledger and report any mismatch. Reason: `Balance` is already fetched but unused; a ledger type the mapper misses (staking, dust conversion, airdrop) would otherwise skew value and XIRR silently.
- (S) Database backup in `portfolio-sync`: a daily `VACUUM INTO` copy of the SQLite file with the last N kept, path in the config. Reason: hand-entered coins and imported XTB history exist only in that file and cannot be re-fetched from any API.
- (S) Gold purchase premium per coin: price paid vs NBP melt value on the purchase date, and today's buyback spread, shown separately from the gold price move. Reason: gold's P&L starts negative by the dealer premium, and without the split the "earned the least" ranking mixes price moves with buying costs.
- (S) XTB export self-check: after parsing Cash Operations, compare the share count it implies with the "Open Positions" sheet of the same file and refuse or warn on a mismatch. Reason: the parser ignores the snapshot sheets, yet they are a free cross-check that no purchase line (e.g. an odd fractional fill) was misread.
- (S) Early warning for a missing IKZE limit: from December, show a notice when `[ikze.limits]` has no entry for the coming year (and an error banner if the current year is missing). Reason: `ikze::ikze_year` returns an error without the year's limit, so on 1 January the IKZE page would break until the config is updated by hand.
- (M) IKE account support next to IKZE: a per-year IKE limit in the config, contributions this year vs the limit, and IKE/IKZE shown as separate wrappers of the VWCE position. Reason: CLAUDE.md says an IKE will be added and the XTB importer already maps an "IKE" account, but nothing in `core` or the config tracks its limit.
- (S) Data-source health check: a `portfolio-sync check` subcommand that makes one read request to each source (NBP table A and gold, Kraken public Ticker, Kraken private Balance, Alpha Vantage) and prints OK / error / latency per source, without writing to the DB. Reason: CLAUDE.md requires checking that a source responds before relying on it, and Stooq already broke silently once; today the only way to find out is to open a page and see a missing price.
- (S) Price sanity guard on stored closes: reject a zero or negative close and flag a day-over-day move beyond a per-class threshold from the config (e.g. VWCE 15%, crypto 40%, gold 10%) as suspect, keeping it out of valuation until confirmed by the next fetch. Reason: one bad close from Alpha Vantage or a Kraken OHLC candle would silently skew value, XIRR, the chart and the "earned the most / least" ranking.
- (M) Fixture demo database and screenshot script: a command that builds an anonymised demo DB from committed fixtures (ledger, recorded prices and FX, no network) and a script that renders every page in light, dark and phone width with headless Chromium into `docs/screenshots/`. Reason: CLAUDE.md requires fixture-based light/dark screenshots in every UI PR, and P21–P24, P29 and P30 are all still ahead, so one shared, repeatable setup beats each PR improvising its own.
- (M) After-tax liquidation value: per asset and in total, an estimate of what selling today would leave after tax, with rates in the config (crypto gains outside a wrapper under PIT-38, IKZE payout taxed as a lump sum, physical gold tax-free when sold more than 6 months after the end of the month of purchase), shown next to the pre-tax figures. Reason: `ikze.rs` already notes the payout tax is not estimated, and comparing a taxed crypto gain with a tax-free gold gain pre-tax distorts the profit ranking.
- (S) Remember a failed price source for a few minutes: after a provider error, use the last stored close without asking it again until a short cool-down (e.g. 5 min) passes or Retry is pressed. Reason: while Alpha Vantage is down, one Overview load asks it once per lookup (position, benchmark, periods, chart, chart benchmark), each waiting out the client's 5 s spacing, so the page takes about 20 s.
- (S) XTB data freshness: show "XTB history up to <date of the latest imported operation>" on Overview and IKZE, and a reminder when it is older than N days (N in the config). Reason: XTB has no API, so an IKZE deposit made after the last manual export is simply missing from contributions, value, XIRR and the remaining IKZE limit, and P30's stale badge covers prices only.
- (S) Date on a gold coin's manual dealer quote: store when the quote was entered, show its age in the coins table, and mark it stale after N days (config). Reason: `manual_quote_pln` has no date and overrides the NBP-based value for good, so a quote from a year ago keeps valuing the coin at last year's gold price without any sign.
- (M) Yearly crypto tax summary for PIT-38: per calendar year, proceeds from crypto sold for fiat, acquisition costs, and costs carried over from earlier years, from the stored Kraken ledger, as a page or CSV export. Reason: Polish rules let unused crypto purchase costs carry forward year to year, which is tedious to track by hand, and the ledger needed for it is already synced.
- (S) Catch up missed snapshot days in `portfolio-sync`: before today's snapshot, write the days since the latest stored one (at most ~10, oldest first, each all or nothing as today), so a Mac that was off or asleep through 22:30 leaves no gap. Reason: launchd skips a day the Mac is off and the README asks for a manual `--date` per day, while the snapshot history and the monthly summary (P26) compare stored days; past days need no extra Alpha Vantage requests beyond the one daily series fetch.
- (S) Drift alert threshold: a `drift_alert_pp` value in the config; the Allocation page and the monthly Telegram summary (P26) flag any class (and BTC/ETH within crypto) whose drift from target exceeds it, with the PLN amount that would close the gap. Reason: drift is only visible when the Allocation page is opened, and the monthly summary, the one push channel, says nothing about allocation, so a large drift can go unnoticed for months.
- (M) Price vs currency split of P&L: for VWCE, BTC and ETH, split each asset's PLN P&L into the move of its EUR price and the move of the EUR/PLN NBP rate since each purchase, shown on the asset card and in the portfolio report. Reason: every one of these assets is priced in EUR and converted at NBP, so today's P&L silently mixes the fund's performance with the zloty's moves, which can change the "earned the most / least" ranking.
- (S) Fees paid summary: total recorded fees per account (XTB, Kraken) and per calendar year, in PLN and as a share of that year's net contributions. Reason: fees are already stored as separate transaction rows but only appear folded into per-asset cost and the unexplained rest of the P&L, so their total cost is never visible.
