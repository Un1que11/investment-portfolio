# Portfolio — личный инвестиционный дашборд

## Цель
Один локальный дашборд, который показывает весь портфель Миши в PLN: сколько вложено, сколько заработано, какой актив принёс больше и какой меньше, и насколько текущее распределение отклоняется от целевого. Работает локально на MacBook (macOS, Apple Silicon).

## Активы и целевое распределение
| Класс | Цель | Внутри | Где хранится |
|---|---|---|---|
| VWCE | 55% | — | IKZE в XTB (позже добавится IKE) |
| Крипта | 25% | BTC 75% / ETH 25% | Kraken |
| Золото | 20% | физические монеты 1/10 oz | вручную |

Цели хранятся в `config.toml`, а не в коде.

## Стек
- Rust (stable), Axum, SQLite через sqlx (миграции в `migrations/`)
- Шаблоны: askama + htmx; графики: uPlot или Chart.js (подключаются с CDN)
- Парсинг xlsx: calamine
- Фоновые задачи: отдельный бинарь `portfolio-sync`, запускается через launchd
- Базовая валюта: PLN. Все суммы хранятся как `rust_decimal::Decimal`, никогда не как f64

## Источники данных
- **XTB:** API отключён с 14.03.2025. Единственный источник — экспорт истории счёта из xStation (xlsx), который Миша загружает вручную через страницу импорта. Импорт должен быть идемпотентным: повторная загрузка того же файла не создаёт дублей.
- **Kraken:** private REST API (Ledgers, TradesHistory, Balance) с read-only ключом. Ключ хранится в macOS Keychain или в `.env`, который не коммитится.
- **Золото:** ручной ввод монет (дата, цена покупки в PLN, вес 3,11 г). Оценка = цена NBP за грамм × вес × коэффициент выкупа из конфига, с возможностью ручной котировки.
- **Цены:** курсы валют — NBP API (таблица A); крипта — Kraken public Ticker; VWCE — Stooq CSV (`vwce.de`, EUR). Перед использованием проверь, что источник отвечает. Если нет — предложи альтернативу в PR, не выдумывай.

## Ключевые расчёты
- Вложено (чистые взносы) vs текущая стоимость, P&L абсолютный и в процентах
- Доходность с учётом времени взносов (XIRR) — по портфелю и по каждому активу
- Вклад каждого актива в общую прибыль (рейтинг «принёс больше / меньше»)
- Отклонение от цели в п.п. и в PLN; калькулятор «у меня есть N zł — как разложить покупки, чтобы приблизиться к цели без продаж»
- IKZE: внесено за год, остаток лимита (2026: 11 304 zł, лимит по годам в конфиге), оценка налогового вычета при ставке 12% или 32% (из конфига)
- Бенчмарк: «если бы все взносы шли в VWCE в те же даты»

## Правила автономной работы
1. За одну сессию берёшь **одну** первую незакрытую задачу из `BACKLOG.md`.
2. Работаешь в отдельной ветке `feat/<id>-<slug>`, открываешь PR, в описании пишешь, что сделано и как проверить.
3. `cargo fmt`, `cargo clippy -- -D warnings` и `cargo test` должны проходить до открытия PR.
4. Каждый расчёт покрыт юнит-тестом с посчитанным вручную примером.
5. Никогда не коммить ключи, реальные выгрузки и реальные суммы. Фикстуры — только обезличенные.
6. Никаких запросов к API, кроме чтения. Никаких торговых операций.
7. Если задача упирается в недостающую информацию (например, формат реального экспорта XTB) — пометь её `BLOCKED: <вопрос>` в BACKLOG и переходи к следующей.
8. После выполнения отметь задачу `[x]` в BACKLOG в том же PR.

## Режимы работы: день и ночь
- **День (вручную, Миша запускает сам):** тяжёлые задачи из бэклога — по одной, по правилам выше.
- **Ночь (запланированная задача):** только лёгкая работа:
  1. Ревью открытых PR: оставить комментарий с найденными багами, рисками и пропущенными тестами.
  2. Багфиксы: если в открытом PR падают проверки или ревью нашло явный баг — исправить коммитом в ту же ветку.
  3. Если открытых PR нет или они в порядке — взять первую незакрытую задачу с пометкой `[light]` из BACKLOG.md.
  4. Тяжёлые задачи (без `[light]`) ночью не начинать. Если лёгких нет — ничего не делать и коротко об этом сообщить.
- Пометку `[light]` Миша ставит сам; ночью её не ставить и не снимать.
